# Bansuri Mapper for Android and iOS

One React Native + Expo SDK 58 application for Android, iPhone, and iPad. These
are native controls and vector hole diagrams, not a WebView. The web target is
also available for previewing and testing the shared interface.

## Run

Use a Node.js version supported by Expo SDK 58 and npm. From this directory:

```powershell
npm ci
npm start
```

Open the QR code in a matching SDK 58 version of Expo Go on a physical Android
or iOS device. The device and development computer need network connectivity.
`npm run android` or `npm run ios` builds locally and opens an available target;
`npm run web` opens the web preview. The iOS Simulator requires macOS and Xcode.

The committed lockfile and exact Expo patch pin keep installation reproducible.
Expo 58.0.24 is used because the configured package feed initially had newer
Expo metadata than its available Router/Jest packages. Upgrade the SDK and its
compatible packages together with `npx expo install --fix` and rerun checks.

## Native builds

Native project directories are generated by Expo Continuous Native Generation,
not manually maintained. App names, identifiers, icons, orientation and plugins
are configured in `app.json`; do not hand-edit generated files.

Local Android build with a configured Android SDK/JDK:

```powershell
npx expo prebuild --platform android
npm run build:android
```

On Windows, `scripts\Build-Android.ps1` builds an ARM64 APK without needing a
connected device, and copies it to `artifacts\bansuri-mapper-android.apk`:

```powershell
.\scripts\Build-Android.ps1 -AndroidSdk $env:ANDROID_HOME -JavaHome $env:JAVA_HOME
```

The helper requires SDK platform 37.0, build-tools 37.0.0, NDK 27.1.12297006,
CMake 3.31.6, a compatible JDK, and Windows long-path support. It selects a
newer Ninja/CMake for deep checkout paths and temporarily aliases SDK paths
containing spaces, cleaning up that alias afterward. Pass `-Architectures
"arm64-v8a,x86_64"` for a multi-architecture APK. Regenerate with
`npx expo prebuild --platform android --no-install` after changing native app
configuration. Local builds use development signing, not store credentials.

Local iOS build on macOS with Xcode:

```sh
npx expo prebuild --platform ios
npm run build:ios
```

These commands build and run locally; a physical target or emulator/simulator is
needed to launch. Local Android release builds use the generated development
signing setup until you configure production signing. Do not distribute that
build as a store release.

`eas.json` also provides these cloud build profiles:

```powershell
npx eas-cli@latest build --platform android --profile preview
npx eas-cli@latest build --platform ios --profile simulator
npx eas-cli@latest build --platform ios --profile preview
npx eas-cli@latest build --platform all --profile production
```

`preview` produces an Android APK or an iOS internal-distribution build;
`simulator` produces an iOS Simulator build; `production` uses an Android AAB
and iOS store build. Cloud builds require your Expo project/account, and iOS
device/store signing requires your Apple team and provisioning. These commands
upload source to Expo; no cloud build, signing, or publishing is done automatically.
Before a store release, replace `com.bansurimapper.mobile` with your own unique
Android package/iOS bundle identifier. Keep signing credentials out of Git.

## Validate

```powershell
npm run typecheck
npm run lint
npm test
npm run test:android
npm run export
npx expo-doctor
```

After exporting, browser smoke tests exercise the rendered shared UI at phone
and tablet sizes and save screenshots in `artifacts\playwright`:

```powershell
npx playwright install chromium
npm run test:ui
```

To use an already installed Microsoft Edge instead, set the
`PLAYWRIGHT_CHANNEL=msedge` environment variable before `npm run test:ui`.
The preview server binds only to localhost and is stopped when the tests finish.

Tests generate 45,504 expected cases by executing the original HTML JavaScript
in `..\Tests\Reference.html`, then compare every thaat, root pair, spelling mode,
alternate setting, and scale note against the mobile mapper. Component tests
exercise the actual selectors, note buttons, alternate switch, reset, modal
cancellation, and reference links. Exports verify that Android, iOS and web
JavaScript bundles compile; they are not substitutes for native device testing
or signed APK/IPA builds.

Expo Doctor may report newer Expo/Router/Jest patch versions than the configured
package feed currently provides. The project keeps a consistent SDK patch set
instead of suppressing these diagnostics; upgrade together once those packages
are available in your feed.

## Structure and behavior

- `src/app`: Expo Router entry and root layout.
- `src/domain/mapper.ts`: platform-independent calculations and state reducer.
- `src/screens/MapperScreen.tsx`: responsive phone/tablet screen.
- `src/components`: accessible choice dialogs and six-hole diagrams.
- `__tests__`: original-app parity and interaction regression tests.

All original swaras, thaats, independent flute keys, pitch/frequency readouts,
register hints, alternate Pa, reset, tuning guidance and source links are kept.
Marwa still omits Pa, and F-sharp through B still use tonic pitches below C4.
Settings reset to C/Bhairav on launch, matching the original. No audio, account,
analytics, storage, or microphone permission is added. Calculations work offline;
opening the two reference websites requires a browser/network connection.

On phones, choosing a note scrolls its fingering detail into view. Larger tablet
windows show detail and map side by side. Safe areas accommodate system bars and
notches; labels and state descriptions are exposed to accessibility services.

The checked-in PNG icons are generated by `scripts\Create-Icons.ps1` on Windows;
this script is not required to run or build the application.
